# LÓGOS AI Release Notes (V1.0.0-Beta)

We are thrilled to announce the Beta release of LÓGOS AI, the ultimate sovereign, local-first AI command center. This release marks the culmination of a massive security and architectural remediation effort to ensure that your agentic workflows are safe, private, and robust.

## Key Improvements in this Release

### 🔒 Security and Hardening (Phases 0 & 1)
- **Path Jailing:** All agent filesystem tools have been strictly jailed. Directory traversal vulnerabilities (`../`) are now actively blocked, restricting agent operations safely to designated `workspace/` and `uploads/` directories.
- **Normalized Environments:** Standardized `.env.example` configurations, hardened `.gitignore` rules, and enforced UTF-8 normalization across all data boundaries to prevent encoding attacks.
- **CORS & Origin Safety:** Removed wildcard CORS rules. The API now strictly enforces origin matching, preventing malicious websites on your network from issuing commands to your local LÓGOS AI instance.
- **No Remote Telemetry:** Verified zero-telemetry posture. LÓGOS AI does not report usage data or crash logs to any external servers.

### 💾 Data & Memory Architecture (Phases 2 & 3)
- **Authoritative Persistence:** Migrated to a robust SQLite architecture utilizing WAL (Write-Ahead Logging) mode, providing atomic, concurrent reads and writes for the agent's Episodic Memory Palace.
- **Centralized Path Resolution:** Eliminated ad-hoc pathing in favor of a secure, central path resolver to ensure database schemas and artifact directories map correctly regardless of the execution environment.
- **Artifact Serving:** Artifacts generated by the AI are now served under a restricted sandbox context, preventing malicious HTML/JS execution.

### 🧠 Safe Agent Runtime (Phase 4)
- **Job Orchestration:** Implemented safe job queues for long-running generation tasks (e.g., ComfyUI image generation or local LLM inference) preventing the event loop from being blocked.
- **Tool Validations:** Hardened prompt constructions. The backend now aggressively validates any tools invoked by models, preventing unauthorized privilege escalation.

### 🎨 Frontend and Accessibility (Phase 5)
- **API Client Modernization:** Completely overhauled the React frontend (`App.jsx`). Manual `fetch()` calls were eliminated in favor of a robust, centralized `apiClient` supporting stream abortion and standardized error handling.
- **Dynamic Model Resolution:** Hardcoded model fallbacks have been removed. The system now dynamically polls Ollama for available models and gracefully falls back to configured environment settings (e.g., `UTILITY_MODEL`), preventing fatal `404` crashes.
- **Persona Forge Defaults:** Seeded personas now come fully pre-configured with rich defaults for Core Expertise, Personality Style, and Quirks, perfectly aligned with their specific identities.
- **Screen Reader Compatibility:** The UI now correctly implements `sr-only` landmark elements (such as `<h1>`) and focus rings, ensuring accessibility for visually impaired users and keyboard navigators.
- **Error Boundaries:** Introduced a top-level React Error Boundary to catch UI rendering crashes and provide graceful recovery workflows.

### 🧪 Quality Assurance (Phase 6)
- **Automated CI/CD:** Integrated GitHub Actions for continuous linting, unit testing (Vitest), and end-to-end browser testing (Playwright).
- **Axe-Core Validated:** Routine accessibility tests run against the UI to catch contrast and semantic violations before they merge.
